## Principles

- **Logic in `core/`.** Anything testable without a window lives in `nightgrid-core`. The Tauri crate only adapts types, holds state and wires events.
- **Typed end to end.** Command signatures and the types they use derive `specta::Type`; `ui/src/lib/bindings.ts` is regenerated by `cargo test -p nightgrid --lib bindings` (and on every debug launch). CI fails if the committed file is stale.
- **Request/response vs streams.** Commands for request/response. From M1, terminal I/O, logs, metrics and transfer progress use `tauri::ipc::Channel` per stream, throttled on the Rust side.
- **No secrets at rest outside the keychain.** SQLite stores a `SecretRef` (kind + owner id) at most; values live in the OS keychain. `Secret` redacts itself in `Debug`/`Display` and zeroizes on drop. A test fails if a table grows a column named like a secret.

## SSH and terminals (M1)

- **Connect flow:** `term_open_ssh` resolves the host (and its ProxyJump chain, where hop names that match saved hosts use those hosts' settings) into targets, then asks the per-host pool for a connection. Errors that need the user (`HostKeyUnknown`, `HostKeyChanged`, `PasswordRequired`, `PassphraseRequired`) come back as data, the UI shows a prompt, then calls `ssh_trust_host_key` / `ssh_provide_secret` and opens again.
- **One connection per host:** shell channels (and later SFTP, metrics, Docker) multiplex over it. Concurrent opens share one connect attempt.
- **Streams:** each terminal gets a `tauri::ipc::Channel<TermMessage>`; output is base64 bytes (not always UTF-8), plus status and exit events. Input goes back through `term_write`.
- **Reconnect:** when the transport drops, the shell task retries with backoff (1–30 s) and writes `[nightgrid] reconnected` into the terminal. Errors that need the user stop retries until "Retry".
- **Edit in Nightgrid:** with the setting on, `term_open_ssh` gets a per-start token and runs `edit_hook::bootstrap_command` instead of a plain shell. xterm's OSC 7766 handler in `TermSession` opens the requested path with `files.openFromTerminal`, and closing that tab writes the token back to the PTY so the remote helper returns (D-030).
- **Panes:** each pane is a `TermSession` owning an xterm instance whose DOM element outlives Svelte components, so splitting/moving panes or switching tabs/sections keeps scrollback. The Terminal view stays mounted while hidden. xterm uses its DOM renderer (no WebGL) with a transparent theme background; `TermPane` attaches the element on mount and detaches it in a teardown that uses only values captured at mount. `refit()` waits two frames, fits, sends the PTY size, then repaints; `remeasure()` (font loads, re-attach) makes xterm measure cells again (D-089). `terms.goToHost` reuses a host's open shell; the **+ NEW** menu (`NewTermMenu`) opens a host or local shell as a tab or split.

## Files (M2)

- **One `Fs` type** (`core/src/files`) covers this machine and remote hosts, so the browser, editor and transfers don't care which side they're on. Remote is an SFTP session on the host's pooled connection, cached per connection (`SftpCache`).
- **Paths are strings in the side's own syntax** (POSIX on hosts, native locally). The UI never joins paths; commands take `dir` + `name`, and listings return full paths and the parent.
- **Editor saves** go through `files::text::save_text`: stamp check → temp file with mode/owner → atomic replace (D-021), with in-place fallback.
- **Transfers** (`files::transfer::Transfers`) run up to 3 jobs as Tokio tasks. Progress lives in atomics; a 250 ms ticker computes speed and pushes the whole job list to the UI over one `Channel` when something changed. Pause/cancel are flags checked between 256 KiB chunks; resume continues from the destination's size.
- **Connection prompts** (host key, password) surface from file commands as `FilesError.connect`, and the pane shows the same prompts as the terminal.

## Docker (M3)

- **Transport** (`core/src/docker/transport.rs`): bollard with a custom transport. Each request opens an SSH channel (streamlocal to the socket, or `docker system dial-stdio`), does a hyper HTTP/1.1 handshake on it, and sends the request in origin form. See D-025 and D-026.
- **`DockerHost`** (`core/src/docker/mod.rs`) wraps one engine: probe and route choice, container list → `ContainerView` (compose labels, health from the API or the status text, ports with v4/v6 folded), `stats` (CPU from the pre/post sample delta, memory minus inactive file cache, like `docker stats`), actions (304 "already in that state" counts as success), `inspect` → `ContainerDetail` (env values masked in `raw`), and `logs` (frames reassembled into lines, timestamps split off, ANSI stripped, sent in batches every 80 ms or 1000 lines).
- **App layer** (`app/src/docker_cmd.rs`): `DockerCache` per host on the pooled connection, log streams as Tokio tasks in `AppState.log_streams` (aborted on stop), and `term_open_docker_exec` for container shells. Errors come back as `DockerCmdError { connect, docker }`, so the view can show SSH prompts or the docker-group hint.
- **Compose stacks** (`core/src/docker/compose.rs`): `stacks()` merges label-derived projects with compose files found by scanning the host's stack folders (`stack_dirs` table). `compose()` runs `docker compose` on an exec channel, streams cleaned lines (ANSI and `\r` redraws removed), cancels with SIGINT, and for "update" diffs service image ids before and after. App side: `docker_stacks`, `docker_compose_run` (output over a Tauri `Channel`, cancel switch in `AppState.compose_runs`), `docker_compose_cancel`, `stack_dirs_*`. UI: `stores/stacks.svelte.ts` and `components/docker/StacksPanel.svelte`.
- **UI**: `stores/docker.svelte.ts` polls the list and stats every 5 s while the view is mounted. `views/Docker.svelte` groups by project. `components/docker/ContainerPanel.svelte` (details/env/labels/raw) and `ContainerLogs.svelte` (virtualised, merges batches per animation frame).

## Monitoring (M4)

- **Collection** (`core/src/metrics/mod.rs`): the `COLLECT` script (D-036) → `parse()` → `Raw` snapshot → `Collector::sample()` → `Sample` (CPU total and per core, load, memory/swap, mounts with usage, per-interface and per-disk rates, temperatures with a best-guess CPU temperature). The first sample of a run has no CPU % or rates.
- **History** (`core/src/metrics/history.rs`): `MinuteAverager` turns samples into `Point`s, `Store::insert_metric_point` writes the minute row and folds it into the 15-minute rollup, `metric_history` picks the resolution by range, `prune_metrics` applies retention (D-037).
- **Pollers** (`app/src/metrics_cmd.rs`): `MetricsHub` in `AppState` holds one Tokio task per host, the visible-host set and the event `Channel`. Each poller connects through the shared `SshPool` without prompting (D-038), runs the script with a 15 s timeout, and sends `MetricsEvent::Sample` / `MetricsEvent::State`. Commands: `metrics_subscribe`, `metrics_sync` (after host or setting changes), `metrics_set_visible`, `metrics_retry`, `metrics_history`.
- **UI**: `stores/metrics.svelte.ts` keeps the latest sample and ~5 minutes of sparkline values per host and merges "visible" requests from the Overview and the monitor panel. `components/metrics/`: `HostTile` (Overview), `HostMonitor` (modal with cores, mounts, interfaces, disks, temperatures and the history chart), `Sparkline`, `Meter`, `HistoryChart` (SVG, gaps for missing minutes, hover readout). In the browser dev mode `mockMetrics.ts` fakes samples and history.
- **GPUs and forecasts** (M10c): the script's `@@nvidia` / `@@drm` sections become `Sample.gpus` (`parse_nvidia`, `parse_drm`) and the busiest GPU is stored as `Point.gpu` (D-068). `ui/src/lib/metrics/forecast.ts` fits a line to 14 days of rollups for the disk and memory forecasts in the monitor (D-067).

## Updates (M4.5)

- `app/src/update_cmd.rs`: `update_check` (plugin `check()` against `latest.json`, keeps the found `Update` in `PendingUpdate`) and `update_install` (download with progress over a `Channel`, verify, install, `app.restart()`). The public key is `app/updater.pub`; an empty key means `notConfigured`.
- CI: with the `TAURI_SIGNING_PRIVATE_KEY` secret set, builds add `createUpdaterArtifacts` (signed `.app.tar.gz`, NSIS `.exe.sig`, AppImage `.sig`). The release job runs `scripts/updater-manifest.mjs` to write `latest.json` and publishes a regular (latest) release.
- UI: `stores/updates.svelte.ts` (launch check, skip, install), `components/update/UpdateDialog.svelte`, Settings → Updates.

## Services (M5)

- **Model** (`core/src/services/mod.rs`, migration 0006): `services` (URL, group, optional host, check settings, `source`/`source_key` for imports) and `service_checks` (one row per check, 30 days).
- **Checks** (`core/src/services/check.rs`): `check(url, expect, allow_untrusted, timeout)` → `CheckResult` (up, status, latency, error, `TlsInfo`). TCP + rustls (`rustls-platform-verifier` wrapped by a capturing verifier) + hyper HTTP/1.1, no redirects (D-045).
- **Homepage** (`core/src/services/homepage.rs`): `parse_services`, `parse_layout_order`, `Store::import_homepage` (sync keyed on `group/name`, D-046).
- **App** (`app/src/services_cmd.rs`): `ServicesHub` runs one checker task (interval from settings, 8 parallel, woken on edits) and pushes `ServiceEvent`s over a `Channel`. Homepage commands read files through the same `Fs` as the Files view; `homepage_detect` uses the Docker client.
- **UI**: `stores/services.svelte.ts`, `views/Services.svelte`, `components/services/` (`ServiceCard`, `ServiceEditor`, `HomepageImport`); `mockServices.ts` for browser dev.

## Tunnels (M5)

- **Model** (`core/src/tunnels/mod.rs`, migration 0007): `tunnels` per host (kind, bind, destination, auto-start).
- **Forwarding** (`core/src/tunnels/forward.rs`): `listen`, `serve_local` (`direct-tcpip` per connection), `serve_dynamic` (SOCKS5 from `socks.rs`, then `direct-tcpip`), `request_remote` + `serve_remote` (`tcpip-forward`; incoming `forwarded-tcpip` channels are routed by the russh handler through `Connection::forwards`). `Stats` counts bytes at the local end. Each loop ends when the SSH connection closes or the future is dropped.
- **App** (`app/src/tunnels_cmd.rs`): `TunnelHub` holds one task per running tunnel (connect via the pool → serve → backoff and retry), the states, temporary forwards (negative ids) and a 1 s stats ticker. `connect_host` calls `host_connected` so auto-start tunnels follow reconnects (D-047).
- **UI**: `stores/tunnels.svelte.ts` (states, traffic, per-second rates, `openThrough`), `views/Tunnels.svelte`, `components/tunnels/TunnelEditor.svelte`; `mockTunnels.ts` for browser dev.

## System (M6)

- **sudo** (`core/src/system/sudo.rs`): `probe` (uid + `sudo -n true` in one round trip), `wrap` (`sudo -S -k -p <marker> -- sh -c …`), `run` (collects output) and `stream` (per-line callback, cancel = SIGTERM + close). The password is written to the channel followed by EOF; sudo's own failures are classified into `SystemError` (D-048).
- **systemd** (`systemd.rs`): one exec lists units and unit files and merges them; `status`; `act` runs `systemctl <verb> -- '<unit>'` as root. Unit names are validated before use.
- **journal** (`journal.rs`): builds `journalctl -o json …` from a `JournalQuery` (unit, priority, since/until, lines, follow; all validated and quoted) and parses entries.
- **packages** (`packages.rs`): one exec detects the manager, lists upgrades and reboot-required signals; `upgrade_command` per manager (D-049).
- **smart** (`smart.rs`): scans and reads every disk in one root session and judges health; fixtures in `core/src/system/fixtures/`.
- **schedule** (`schedule.rs`, M10c): one unprivileged script reads timers (`systemctl show --timestamp=unix`), their services' last result, crontabs and `cron.<period>` folders; `CronSpec` parses 5-field schedules and finds the next run in host time; `describe` words common schedules (D-066). Command: `system_schedules`; UI: `SchedulesPanel.svelte`.
- **security** (`security.rs`, M10d): one unprivileged script → `parse_audit` → `SecurityReport` (checks with status, weight and fix text; listeners with scope, process and container; score and grade) (D-069). Command: `system_security`; UI: `SecurityPanel.svelte` (per host, and the port map that audits every host three at a time).
- **App** (`app/src/system_cmd.rs`): `resolve_sudo` (probe → prompt input or keychain → `sudo true` check), commands for units, journal (stream with batching), updates, upgrade runs, reboot and disks. Streams share a stop switch map (`system_runs`).
- **UI**: `stores/system.svelte.ts` (per-tab state, `withSudo` retry loop around the prompt), `views/System.svelte`, `components/system/*`; `mockSystem.ts` for browser dev.

## Alerts and tray (M7)

- **Rules** (`core/src/alerts.rs`): `Tracker` (pending → active → resolved, grace and clear-hold per kind, scoped reports, 200-entry history), condition builders for host offline, disk usage, services/certificates, SMART and containers (`ContainerWatch`), quiet hours, and webhook request builders (ntfy, Discord, JSON) (D-050, D-051).
- **HTTP** (`core/src/http.rs`): one-request HTTP/1.1 client on hyper + rustls with the OS verifier, bounded body, no redirects; shared TLS setup with the service checker. Used by webhooks now and integrations next.
- **App** (`app/src/alerts_cmd.rs`): `AlertsHub` and its loop (15 s; Docker 60 s; SMART 6 h per host), delivery (notifications via `tauri-plugin-notification`, webhook URL from the keychain), commands for the snapshot channel, history, webhook URL and a test send. Reads `MetricsHub::poll_states/mounts` and `ServicesHub::latest`.
- **Tray** (`app/src/tray.rs`): builds the menu from hosts, tunnels and alert counts, rebuilds on change, emits `tray://connect` / `tray://alerts` to the UI; close-to-tray in `lib.rs`'s window event handler, Dock reopen on macOS (D-052).
- **UI**: `stores/alerts.svelte.ts`, `components/alerts/AlertsPanel.svelte` (opened from the status strip or the tray), `components/alerts/AlertSettings.svelte`; `mockAlerts.ts` for browser dev.

## Built-in Tailscale and DRIFT host facts (M10j)

- **Sidecar** (`tailnet/`, Go, `tsnet`, D-091): `main.go` reads a config line (state key, dir, hostname, accept-routes, control URL) then commands (`login`, `logout`, `acceptRoutes`, `status`, `quit`) on stdin, and writes events (`ready` with the SOCKS address and per-run credentials, `login`, `state`, `status`, `error`) on stdout. `store.go` is the AES-256-GCM `ipn.StateStore` (`node-state.enc`). CI builds it per target into `app/binaries/nightgrid-tailnet-<triple>` and passes it to `tauri build` as `bundle.externalBin`, so it ships next to the app executable.
- **Core** (`core/src/tailnet.rs`): `Sidecar::start/login/logout/accept_routes/stop`, `TailnetStatus`, the process-wide routing table (`route_for`), `dial(host, port, timeout)` (direct, SOCKS5, or direct-then-SOCKS5) and the per-host fallback table (`set_fallbacks`, `active_address`, D-092). `ssh::client::tcp_connect`, `tcp_ping`, `http`, service checks and tunnel forwards all dial through `tailnet::dial`.
- **App** (`app/src/tailnet_cmd.rs`): `TailnetHub` in `AppState`; commands `tailnet_status`, `tailnet_set_enabled`, `tailnet_configure`, `tailnet_login`, `tailnet_logout`; status pushed as `tailnet://status`. The state key is `SecretKind::TailnetStateKey` in the keychain; state lives in `<data dir>/tailnet`. `hosts_cmd::sync_fallbacks` refreshes the fallback table on start-up and on every host list load or change.
- **UI**: `stores/tailnet.svelte.ts`, `components/tailnet/TailnetPanel.svelte` (Settings), the host editor's **Tailnet address** with peer suggestions; browser preview uses `mockTailnet.ts`.
- **DRIFT host facts** (D-093): `helper/hostFacts.ts` (`mentionedHosts`, `hostFacts`) → `HelperContext.hosts`, first block in `contextBlock`. History: `helper_host_history` (`app/src/helper_cmd.rs`) checks `hosts.drift_history` (migration 0016) and reuses `system::history::read_command` / `parse` / `filter`.

## Backups (M9)

- **Core** (`core/src/backup.rs`): `snapshot` copies the config tables into a JSON `Bundle` (history tables left out), `collect_secrets` adds keychain entries on request, `encrypt`/`decrypt` wrap it in an age scrypt passphrase file, `import` merges (natural keys, id remapping) or replaces in one transaction, and `restore_secrets` moves keychain entries to the new ids (D-057, D-058).
- **App** (`app/src/backup_cmd.rs`): `backup_export`, `backup_open` (decrypt + summary, remembers the picked path), `backup_import`, sync folder commands and `app_restart`. Native file dialogs run in Rust via `tauri-plugin-dialog`, with no webview permission (D-059).
- **UI**: `components/backup/BackupPanel.svelte` in Settings, helpers in `stores/backup.ts`, `mockBackup.ts` for browser dev.

## DRIFT helper (M10)

- **Runtime** (`llm/`, crate `nightgrid-llm`): llama.cpp through `llama-cpp-2`, Metal on macOS and CPU elsewhere. `Engine::load` opens a GGUF file; `generate` applies the model's own chat template, decodes the prompt in batches and streams valid UTF-8 pieces, stopping at end of turn, a token limit or a cancel flag. An over-long conversation is refused, never silently truncated. llama.cpp logs go to `tracing` (D-064).
- **Model** (`core/src/helper/model.rs`): one pinned `ModelSpec` (URL fixed to a repository commit, size, SHA-256). `download` resumes with `Range`, follows redirects only to allow-listed hosts over verified TLS, hashes as it writes, deletes the file on a checksum mismatch and drops a `.sha256` marker when done, so `state()` doesn't re-hash on start (D-063).
- **App** (`app/src/helper_cmd.rs`): `helper_status`, `helper_download` (progress over a `Channel`), `helper_cancel_download`, `helper_delete_model`, `helper_unload`, `helper_ask` (loads the model once, streams `HelperEvent`s, refuses while the helper is off) and `helper_stop`. Models live in `<app_data_dir>/models/`.
- **UI**: `helper/knowledge.ts` chunks the bundled `docs/USER_GUIDE.md` and ranks chunks with BM25; `helper/prompt.ts` builds the turns (system prompt with the "show me" targets, guide sections, view/host/selection context), masks secret-looking values and parses `[[show …]]` / `[[point …: …]]` lines; `helper/guide.ts` lists the `data-guide` targets (a test checks they exist); `helper/md.ts` renders replies as text nodes only. `stores/helper.svelte.ts` holds the conversation and spotlight; `components/helper/` has the panel, the DRIFT sprite (drawn from `docs/mascot/drift-sprites.json`), the spotlight overlay and the model card.
- **Explain** (`components/helper/ExplainButton.svelte`): views pass a source label and a function that gathers their text; a selection inside the view wins. `helper.explain()` attaches it as context (`HelperContext.source`) and asks, or leaves the question in the box if the model isn't ready (D-065).

## Storage

- One SQLite file: `<app_data_dir>/nightgrid.db`, WAL mode, `foreign_keys=ON`.
- Migrations are SQL files in `core/src/store/migrations/`, applied in order by `rusqlite_migration`. Never edit a shipped migration; add a new one.
- Settings are JSON values in a `settings(key, value)` table. `AppSettings` uses `#[serde(default)]` so new fields don't break old databases, and invalid stored values fall back to defaults.

## Frontend

- **Design tokens** in `ui/src/styles/tokens.css` (first paint) and `ui/src/lib/theme/themes.ts` (runtime source of truth). A vitest keeps them in sync and checks WCAG AA contrast for body text in every theme.
- **Effects** are gated by `data-effects="on|off"` on `<html>`, computed as `theme.effects && !reduceEffects && !prefers-reduced-motion`. Off zeroes durations and glow, hides scanlines and skips the scramble effect.
- **Visual language:** sharp 1px hairline boxes with wide-tracked uppercase labels; magenta = selected/active (with glow), mint = completed/neutral highlight, yellow = primary action and keyboard focus, cyan = data and prefixes. Chamfers are reserved for primary buttons and the palette. Decorative barcodes/hex IDs appear only in headers, margins and the status strip.
- **Keyboard:** all shortcuts are defined in `DEFAULT_KEYMAP` (`ui/src/lib/keys.ts`) using `Mod` = Cmd on macOS / Ctrl elsewhere, so a rebinding UI can override them later.
- **Handheld and controllers:** `data-handheld="on"` on `<html>` raises `--hit` (every button, field, toggle and rail item uses it as its minimum size); `ui/src/lib/gamepad.ts` turns Gamepad API snapshots into actions (`PadReader`) and moves focus spatially (`pickNext`, `moveFocus`), started from `App.svelte` with hooks for view switching, the palette and the sidebar (D-060).
- **CSP-safe Svelte:** the CSP has no `'unsafe-inline'`, so components must not use static `style="..."` attributes; use `style:prop={...}` directives (CSSOM) or classes.

## Security posture (M9)

- CSP: `default-src 'self'`, no inline script/style, no remote origins; `connect-src` limited to Tauri IPC. Runtime `<style>` elements (xterm) are mirrored into constructable stylesheets instead of relaxing the CSP (D-013).
- Capabilities: `core:default`, clipboard read/write text (terminal copy/paste) and `opener:allow-open-url` limited to `http(s)://` (links in terminal output) on the `main` window only. App commands are registered explicitly via tauri-specta.
- `freezePrototype` on (with a build step for xterm, D-014); no global Tauri object (`withGlobalTauri: false`).
- SSH secrets: agent preferred; passwords/passphrases come from a prompt or, only with "remember", the OS keychain. They are cached in memory per run (D-016) and never logged or stored in SQLite.
- Host keys: unknown → fingerprint prompt; changed → connection blocked until the user types the host name; `~/.ssh` is never written (D-017).
- Files: delete confirms with the exact target list (and the host name typed for multi-item deletes on a host); overwrites in the transfer queue name the target; overwriting a file changed on the server needs a confirmation. File contents are never logged; logs record paths of deletes and saves only.
- Docker: stop/restart/kill/remove confirm with the exact containers (removing several also needs the host name typed); destructive actions are logged with their targets. Env values are masked in the UI and raw JSON and never logged (bollard debug output filtered). Container references are validated before they reach a URL or shell. Compose down/restart/update confirm with the stack and host named, and are logged; stack names and paths are validated and shell-quoted. No sudo: socket permission problems surface as a docker-group hint.
- Metrics: read-only commands only, no sudo, nothing written on the host. Background pollers never prompt for passwords or host keys; they wait for a connection the user made (D-038). History holds numbers only.
- Services: checks are plain GETs to URLs the user entered or imported (rule 7: their own hosts); URLs with credentials are rejected; untrusted certificates count as down unless allowed per service; imported icons are never fetched. Homepage import only reads files.
- sudo (M6): passwords go to sudo's stdin on the exec channel, never on a command line, in the environment or in logs; prompted per action by default; kept in the keychain only with the per-host "remember" (off by default) and deleted when it stops working; never cached in memory between actions. Root and NOPASSWD hosts skip the prompt. Unit stop/restart/disable confirm with the unit and host named, package upgrades list the packages, reboot needs the host name typed; all of these are logged with their targets. Unit names, journal filters and times are validated and shell-quoted.
- Alerts (M7): background checks never open connections or prompt; SMART only runs where sudo needs no password. The webhook URL is kept in the keychain only and shown back as scheme + host; webhook requests verify certificates before sending and go only to the URL the user saved. Notifications are sent from Rust, so the webview has no notification permission. The tray only emits events; connecting still goes through the UI's normal prompts.
- Integrations (M7): tokens and passwords live in the keychain only, masked in the editor with click to reveal; status is read only while Services is open and only from URLs the user entered; AMP stop/restart confirm with the instance named and are logged; instance names are validated; untrusted certificates are refused unless allowed per integration. Portainer is used for links only, with no token.
- Automation (M8): runs never prompt for SSH logins or host keys (those hosts fail with a Connect button); sudo passwords typed for a run go to sudo's stdin and are dropped, never remembered from here; variable values are shell-quoted into commands; destructive commands (rule 5's list plus `>` overwrites, uploads and Docker stop/restart steps) need a confirmation naming the targets, with the group name or host count typed for several hosts; every run is logged with its hosts, never its output.
- Backups, routes and logs (M10g): backup jobs are read without repository passwords; proxy configs are read through the Docker API and certificates by `openssl` on the host; log anomaly reads are opt-in, keep patterns in memory and drop secret-looking lines; **What broke?** only goes to the local model (D-075–D-077).
- VMs, status page (M10h): VM listing is unprivileged first, root only through the sudo prompt, and destructive guest actions name the guest and host; the status page is off by default, bound to one chosen address, read-only, token in the keychain and masked, with a per-address lockout (D-079–D-081).
- Stacks (M10f): `.env` and compose copies for snapshots stay on the host in a mode-700 folder; registry checks are anonymous and user-triggered; the wizard keeps env values out of `compose.yaml`; rollback and file replacement confirm by name (D-072–D-074).
- Notes and history (M10e): notes refuse secret-looking text on save (D-070); "Send to terminal" pastes and never presses Enter. History search is off by default, reads only the login user's own files, drops secret-looking lines before they reach the UI and keeps nothing (D-071).
- Backups (M9): exports are always age-encrypted with a passphrase (no plaintext option); keychain secrets are included only when ticked, and the plaintext buffer is zeroized; files are written atomically with mode 600; replace needs `replace` typed and first deletes keychain entries of the rows it removes; file dialogs run in Rust, so the webview gained no permission; the passphrase is never stored or logged.
- DRIFT (M10): off by default; the model runs locally and nothing is sent anywhere. The only network use is the model download the user clicks: a pinned URL and SHA-256, redirects limited to Hugging Face hosts, verified TLS. Selected text and the question are masked for secret-looking values before they reach the model, and each reply shows exactly what the model was given. Replies render as text (no HTML), and "show me" only scrolls to and outlines a control; it never clicks or runs anything.
- Tunnels: listeners default to loopback, other bind addresses are flagged as public; SOCKS has no auth for that reason. Auto-start never prompts; a host that needs a login fails with that reason. Remote-forward channels for ports nobody asked for are rejected.

## Platform notes

- **Linux:** WebKitGTK DMA-BUF renderer is disabled automatically on NVIDIA (`/proc/driver/nvidia/version`), overridable with `NIGHTGRID_FORCE_DMABUF` / `NIGHTGRID_DISABLE_DMABUF`, and `WEBKIT_DISABLE_DMABUF_RENDERER` always wins. XDG dirs come from Tauri's path resolver.
- **Flatpak (M9):** will need `--share=network`, `--socket=ssh-auth`, `--filesystem=~/.ssh:ro`, `--talk-name=org.freedesktop.secrets` (Secret Service) and the notification portal.
