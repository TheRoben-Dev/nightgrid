# Set up and rotate SSH keys

Make one good key, put it on every host, see at a glance which key works where, and replace a key everywhere without locking yourself out.

![Your private key stays home; hosts hold only the public half.](fig:ssh-keys)

## What you end up with

- An ed25519 key in `~/.ssh` (optionally with a passphrase kept in the OS keychain)
- A table of every host and every key that it accepts
- Old or leaked keys removed from all hosts in one guided run

## Before you start

- At least one host you can already log in to (password is fine for now).
- Open **Settings → Connections → SSH keys**. It lists key files in `~/.ssh` and the keys your SSH agent holds.

## Part 1 · Make a key

- [ ] **NEW KEY…**: pick a file name (`id_ed25519_nightgrid` or similar), a comment (`you@laptop`) and optionally a passphrase. Nightgrid never overwrites an existing file.
- [ ] A passphrase only encrypts the file. Nightgrid asks for it when it connects and can remember it in the keychain.
- [ ] **Copy public key** copies the `.pub` line, for places outside Nightgrid (a Proxmox container, a git server's deploy keys).

## Part 2 · Put it on your hosts

- [ ] **CHECK HOSTS** reads `~/.ssh/authorized_keys` on every saved host and fills **WHERE THEY WORK**.
- [ ] **+** in a cell adds the key to that host. A filled **●** means the host accepts it; a ringed **●** is the key Nightgrid currently uses for that host.
- [ ] **OTHER** counts keys on a host that aren't yours. Click it and remove ones you don't recognise (you type the host name to confirm).

#### Check

- [ ] Every host has a **●** for your new key.
- [ ] Log in to one host with only that key to prove it.

## Part 3 · Turn off password logins

- [ ] With keys working everywhere, follow [Hardening sshd](kb:basics/sshd-hardening) to set `PasswordAuthentication no`.
- [ ] [System](view:system) → **security** confirms the change in its score.

## Part 4 · Rotate a key

- [ ] **ROTATE A KEY**: pick the old key, the new key and the hosts. Hosts that accept the old key are pre-selected.
- [ ] For each host Nightgrid adds the new key, logs in with only the new key, points the saved host at it, then removes the old key. A failure stops that host with its old key intact.
- [ ] With **Remove the old key** on, you confirm by typing the old key's name.

#### Check

- [ ] **CHECK HOSTS** again: the old key has no **●** left.

## Limits and gotchas

- Nightgrid never edits `~/.ssh/config`. If a `Host` entry there names an `IdentityFile`, update it yourself after rotating.
- Keys held only by an agent (1Password, Secretive) can be added to hosts but not generated by Nightgrid.
- Root logins with keys still count as root logins in the security score; prefer a normal user with sudo.
